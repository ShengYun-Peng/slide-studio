# Allocate a video inference budget

Show the three factors in a video model's inference budget: the number of sampled frames, visual detail represented by tokens, and language-model capacity. The animation follows frames through visual encoding into tokens and then reasoning, before revealing a qualitative cost decomposition. It does not claim an experimentally optimal allocation or display a fitted scaling law.

## Run and inspect

From the repository root on macOS, compile this scene's actual renderer:

```sh
swiftc runtime/renderers/video-budget.swift -o /tmp/slide-studio-video-budget
/tmp/slide-studio-video-budget --config "$PWD/scenes/video-budget/scene.json" --output "$PWD/scenes/video-budget/demo" --video
```

Use `--preview` instead of `--video` for stills. Both modes produce `poster.png`, `end.png`, `contact-sheet.png`, and `render-manifest.json`; video mode also produces `movie.mp4`. The current demo is **1920×1080, 60 fps, 12 seconds**. Review the decoded movie as well as the poster, especially arrow endpoints, small labels, and the final hold. In Keynote, autoplay the movie while keeping slide advancement manual unless continuous advancement is intentional.

## What JSON changes

The renderer reads these `content` strings:

| Field | Visible role |
| --- | --- |
| `title` | Main takeaway above the diagram. |
| `frames_label` | Factor heading under the stacked frames. |
| `frames_detail` | Short explanation of temporal coverage. |
| `tokens_label` | Factor heading under the token grid. |
| `tokens_detail` | Short explanation of visual detail. |
| `capacity_label` | Factor heading under the language model. |
| `cost_label` | Final inference-cost statement. |

`frame_count`, `token_count`, `model_label`, and `model_detail` are **not supported** by this renderer. The module text `Vision encoder`, `Language model`, and `Reasoning capacity` is currently source-defined. There is no `content.labels` replacement map for this scene. Edit the source when those labels need changing.

## Timing

`duration` scales the entire **20-reference-second** sequence uniformly: `reference_time = elapsed_seconds / duration × 20`. With the current 12-second movie, multiply the reference values below by 0.6 to obtain playback times. The empty `timing` object is reserved; neither named events nor a `timeline` anchor map are read by this renderer. To change stage proportions, edit the start/duration expressions in `frame`, `videoCard`, and `render`.

| Reference seconds | Current playback seconds | Visible action |
| --- | --- | --- |
| 0.15–2.25 | 0.09–1.35 | Three sampled frames appear. |
| 2.8–5.9 | 1.68–3.54 | Connect and scan the images; activate the vision encoder. |
| 5.7–10.73 | 3.42–6.44 | Reveal the visual-token grid. |
| 10.8–15 | 6.48–9 | Activate the language model and send it tokens. |
| 13–14.5 | 7.8–8.7 | Reveal the total-cost statement. |
| 15–20 | 9–12 | Hold the completed diagram. |

`poster_time` and `preview_times` are playback seconds. Update them when changing duration. Output dimensions and `fps` remain configurable.

## Fixed topology and assets

The illustration uses **three frame cards**, a **5-column × 4-row grid of twenty tokens**, one vision encoder, and one language model. These are visual examples, not literal experimental settings. The abstract scene inside each frame is generated by code, so this renderer requires **no external image or video asset**. It does not load benchmark footage.

Use `runtime/renderers/video-budget.swift` to change counts, token layout, diagram topology, module text, or colors. Count changes also require retiming the reveal loops, packet flow, and downstream activation; changing one loop bound alone can break the explanatory order. If replacing the abstract sequence with real footage, add explicit local asset loading and provenance rather than pointing to a file in the defense folder.

## Layout and theme limits

Geometry uses a 1920×1080 design canvas and scales with the output dimensions. The renderer currently reads `theme.background` and `theme.foreground`; the other embedded theme fields are project metadata, not controls for this renderer. Semantic colors, line widths, font sizes, and font choices live in the Swift source. Text is drawn at fixed sizes: it does **not** automatically wrap or shrink. Keep replacements short and inspect every affected stage.
